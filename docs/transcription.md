# Transcription

BridgeClip has three per-run clipping modes. **Quality** (the default, including older requests) uses `anthropic/claude-opus-5.5` for planning and prefers `microsoft/mai-transcribe-2` for transcription. **Economy** uses `z-ai/glm-5.3-flash` and prefers `openai/whisper-large-v3-turbo`, with paid layout vision disabled and no higher-cost planner fallback. **Advanced** lets users search OpenRouter for a transcription model and a clip planning model. Automation metadata still uses MAI Transcribe 2. One OpenRouter key covers all modes.

Advanced searches the live [OpenRouter model catalog](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) by model name, provider and ID. The main process reads the public catalog with separate `output_modalities=text` and `output_modalities=transcription` filters; no key is needed for discovery. Results are cached for ten minutes, requests time out after fifteen seconds, response bodies are bounded, and Refresh models retries a failed lookup. Selecting a model never invokes it. A failed refresh preserves existing selections and previously loaded results.

Planning choices must advertise text input, text output and structured outputs. The model's output limit caps BridgeClip's 32,000-token allowance. Advanced uses the model's default reasoning behavior, which also accommodates models without reasoning controls. Text-only planners work with speech transcripts; a silent video requires a model with image input. Catalog availability and task compatibility are validated again in main before queuing, and only validated IDs and bounded capabilities reach the engine. Custom choices travel with each queued job and are shown in Review. Switching to a preset ignores the retained custom choices.

The transcription picker includes models from OpenRouter's dedicated transcription catalog, rather than treating every audio-capable chat model as a transcription model. Known models that reject timestamped transcripts are shown as unavailable. The catalog does not reliably advertise word-timestamp support for all models, so Advanced always requests and validates real word times; unsupported results fail with guidance to choose another model. It does not fabricate caption timing. See [OpenRouter's timestamp contract](https://openrouter.ai/docs/guides/overview/multimodal/stt).

Advanced retries temporary errors using only the selected models: up to two transcription requests per chunk and three planning attempts. It never silently switches to preset transcription or planning models. Optional AI framing checks are still controlled in Format and use the existing Gemini-based framing service. Catalog text prices are shown for planning; transcription prices are not displayed because catalog units vary by provider. Actual reported usage takes precedence; if a custom model omits cost and no reliable estimate exists, results show a partial subtotal instead of a guessed full price.

Transcription recovers automatically from provider failures. Economy tries **Whisper Turbo → Whisper Large V3 → MAI Transcribe 2**; Quality tries **MAI Transcribe 2 → Whisper Large V3 → Whisper Turbo**. A rate limit (429), timeout or temporary server/network failure gets one retry per model, then a fallback. Retry waits include jitter, honor numeric or HTTP-date `Retry-After`, and are limited to 15 seconds. If the provider asks for a longer wait, BridgeClip switches models without retrying that model early. Each chunk has at most six requests across the three models. Unsupported requests/models and missing or invalid word timestamps switch models immediately. Authentication failures, exhausted credits, redirects and oversized responses stop without further requests.

The working fallback is retained for subsequent chunks; completed chunks are not retranscribed. Progress shows part numbers, retry waits and model switches. Word timestamps remain mandatory for captions and cut timing. A 429 is reported separately from a 402 credit/spending-limit failure; a fallback cannot bypass an account-wide limit or a platform-wide outage. Provider choices cannot be pinned on OpenRouter's transcription endpoint, so BridgeClip sends separate supported model requests rather than unsupported chat-routing options.

The engine posts base64 audio JSON to `https://openrouter.ai/api/v1/audio/transcriptions` and requires `verbose_json` with word timestamps for every model. MAI requests Azure speaker diarization and passes custom vocabulary through `provider.options.azure.phraseList.phrases`. Whisper requests do not enable diarization; they pass vocabulary as a Groq prompt hint when Groq serves the request. See the [OpenRouter speech-to-text contract](https://openrouter.ai/docs/guides/overview/multimodal/stt), [MAI Transcribe 2](https://openrouter.ai/microsoft/mai-transcribe-2), and [Whisper Large V3 Turbo](https://openrouter.ai/openai/whisper-large-v3-turbo).

Audio stays at its original speed. Long recordings use five-minute chunks with one second of overlap; word midpoints assign overlap words to one chunk, and timestamps are shifted to the original video timeline. Speaker labels are scoped to each chunk because separate requests cannot establish a person's identity across chunks. Speech without word timing after all fallbacks fails instead of creating fabricated captions; a valid empty transcript can use visual-only planning in either mode. MAI does not supply the old provider's audio-event tags, so those remain empty.

Requests reject redirects and compressed responses, have a 90-second network timeout, and bound both audio and response sizes before buffering. The engine uses returned `usage.cost` when available, including zero; otherwise it estimates at $0.10 per input audio hour for MAI, $0.0108 for Whisper Turbo, or $0.0288 for [Whisper Large V3](https://openrouter.ai/openai/whisper-large-v3), the OpenRouter listed base prices on 2026-09-24. Provider routes can have different prices. Overlap audio and successful responses discarded for unusable timestamps count toward reported usage. Cost details include the models that returned audio transcripts and the total request count. Unknown charges from requests that timed out cannot be reconstructed locally; OpenRouter's billing is authoritative. Automation transcription bounds the combined transcript before metadata generation and uses its separate request path.

`bridge/test_openrouter_transcription.py` covers the request, word timing, speaker 0, chunk offsets, cost reporting, silence, malformed results and safe provider failures. `engine/tests/test_transcription_recovery.py` exercises bounded retries, all fallback paths, `Retry-After`, cancellation, chunk continuity, billed discarded responses, fatal errors, safe error classification, embedded provider errors, and bounded streaming with real httpx and an offline transport. Automation tests exercise the OpenRouter payload with local mock services. Live provider behavior still needs a controlled run with an OpenRouter account; automated tests do not spend provider credits.

## Local transcription

Under **Settings → AI & transcription**, choose **Local Whisper** to transcribe on your own computer instead of OpenRouter. Audio never leaves your machine, there is no per-minute cost, and no OpenRouter key is needed for this step. The result uses the same word-timestamp format as the cloud models, so planning, sentence snapping, captions and cuts behave the same way.

**Built-in** runs Whisper inside BridgeClip's engine. `faster-whisper` is part of the engine's locked requirements, so builds made from this source include it; an engine Python that only has `openai-whisper` still works, more slowly. When running from source, BridgeClip looks for the engine's Python in `engine/.venv`, `engine/venv`, then the repo-root `engine-venv`. If no Whisper is installed, Settings says what to install and a job does not start. Models are installed from Settings with one click (about 75 MB for `tiny`, 480 MB for `small`, 1.5 GB for `medium`, about 1.6 GB for `turbo`). A job does not start until the chosen model is installed, so it never stalls on a silent download. The model stays loaded for the rest of that job.

**Server** sends each five-minute chunk to an OpenAI-compatible `/v1/audio/transcriptions` server at the URL you enter, requesting `verbose_json` with word timestamps. The server must return word timings; a server that returns only segment timings fails with a clear message instead of producing approximate captions. Redirects are refused, the response is bounded, and BridgeClip's network guard allows only that host and port, and only on your own computer or private network.

### Choosing a model

| Model | Speed on a CPU | Use it for |
| --- | --- | --- |
| `tiny`, `base` | Fastest | Quick tests. Names and jargon are often wrong. |
| `small` (default) | About real time on a modern laptop CPU | Good everyday accuracy and punctuation. |
| `medium`, `turbo` | Slower than real time on a CPU, fast on a supported GPU | Best accuracy for names and accents. |
| `large-v3` | Needs a GPU in practice | Highest accuracy. |

A GPU makes a large difference. `openai-whisper` uses CUDA only if your PyTorch is a CUDA build (`torch.cuda.is_available()`); `faster-whisper` uses CUDA when CTranslate2 can find it. Settings → AI & transcription shows which engine and device were found.

### Managing models and the device

With **Local Whisper** and **Built-in** selected, **Settings → AI & transcription** lists every model BridgeClip can use (`tiny`, `base`, `small`, `medium`, `turbo`, `large-v3` and the English-only `.en` versions) in a **Local Whisper models** panel. It shows whether each is installed, its size on disk, roughly how much memory it needs on the CPU and on a GPU, and a short speed and accuracy note. Choosing a row selects that model. A model counts as installed only when the engine's own Whisper has it: an `openai-whisper` copy does not count for `faster-whisper`, because a job would download the model again.

- **Install.** A model that is not installed has an **Install** button with its approximate size. It downloads into the same cache the engine reads from, with a progress bar and **Cancel**. A stopped `faster-whisper` download continues where it left off next time. One download or GPU setup runs at a time, and it keeps going if you leave Settings. The engine's Python runs `engine/clip_engine/services/whisper_setup.py`, which reports progress as JSON lines; the app shows only fixed messages, never the tool's own output. `HTTP_PROXY`, `HTTPS_PROXY` and `NO_PROXY` are passed to the download.

- **Fit warnings.** If a model is unlikely to fit, the panel says so plainly, for example "Needs about 6 GB of video memory; you have 4 GB. Use CPU." The memory figures are approximate guides, not guarantees, and cover the model plus working memory for a five-minute chunk. GPU memory is read from `nvidia-smi` when it is available.
- **Delete.** **Delete** removes an installed model from the cache after you confirm, and tells you how much space it freed. BridgeClip only deletes the known model files inside the two Whisper cache folders (`~/.cache/whisper` for `openai-whisper`, the Hugging Face hub cache for `faster-whisper`), never follows symbolic links, and refuses while a clip job or editor export is running. A deleted model downloads again if you use it.
- **Device.** **Auto** uses the GPU when it works and falls back to the CPU if it does not. **CPU** uses system RAM and never touches the GPU, which is slower but always available. **GPU** is faster but needs enough video memory and the CUDA libraries; if it cannot be used, the job stops with "Local Whisper could not use the GPU" instead of quietly running on the CPU. Choosing GPU on a computer with no CUDA device shows a note in the panel.
- **Enable GPU.** On Windows with an NVIDIA GPU and `faster-whisper`, **Enable GPU** installs NVIDIA's cuBLAS and cuDNN for CUDA 12 into the engine's Python with pip (`nvidia-cublas-cu12==12.9.2.10`, `nvidia-cudnn-cu12==9.27.0.42`, the versions tested with faster-whisper 1.2.1; about 2 GB on disk). It then loads the selected model (or the smallest installed one) on the GPU and transcribes 30 seconds of silence with a job's settings (float16, beam size 5, word timestamps), and names the model it tested. A visible GPU proves nothing about its libraries, so only that test reports the GPU as working. The engine adds the packages' `nvidia/*/bin` folders to the DLL search path and `PATH` before CTranslate2 loads. Enable GPU is refused while a clip job runs, and no job starts while it runs. It is offered only when running from source: an installed app's runtime is replaced by each update. On Linux and macOS the CUDA libraries come from the system.
- **Cache folders.** The scan and the engine use the same cache locations, and honor `XDG_CACHE_HOME`, `HF_HOME` and `HF_HUB_CACHE` if you have set them.

The panel does not appear for **Server** mode, because the server owns its models.

### How quality is protected

- Words are never given invented times. Whisper's word timings are cleaned so words do not overlap, never end after the audio, and last at least 40 ms, because overlapping or zero-length words make captions flicker or stack.
- `condition_on_previous_text` is off so one wrong sentence cannot snowball into the following ones, and segments Whisper itself rates as probably silent and low-confidence are dropped. `faster-whisper` also filters silence with voice activity detection. Whisper is known to invent text such as "Thanks for watching" over silence; these settings are what keep that out of your captions.
- Your **custom vocabulary** from Settings helps Whisper spell names and jargon correctly. It is a hint, not a guarantee. `faster-whisper` receives it as `hotwords`, which it puts before every 30-second window, so it applies to the whole recording; `openai-whisper` receives it as a prompt that it repeats before every window (version 20250625 and later; older versions use it for the first window only), and Whisper servers receive it as a prompt.
- **Spoken language** in Settings sets the language for every chunk. With **Detect automatically**, `faster-whisper` detects the language from up to three 30-second windows of speech, and the language is reused for the rest of the job once a chunk has at least 20 words and Whisper is at least 80% sure of it. That keeps spelling consistent and saves time, and a chunk that is mostly music or silence, such as a stream's intro, does not decide it. A chunk transcribed before the language was settled is not transcribed again; choose the language when you know it. English-only `.en` models always transcribe English.
- Local Whisper does not identify speakers, so transcript lines have no speaker labels. Clip planning works without them; for multi-speaker content, cloud MAI Transcribe 2 still labels speakers.

### Costs

Local transcription is recorded as `provider: local` at $0 with complete cost, so the run's cost total reflects only what you paid other providers.

## Other AI providers

Under **Settings → AI & transcription**, clips can be planned by **Google Gemini** or an **OpenAI-compatible** endpoint instead of OpenRouter. The model is whatever you enter: BridgeClip uses it for clip planning and, when it can read images, for visual-only planning and framing checks. The OpenRouter Quality, Economy and Advanced presets do not apply, because their models are OpenRouter ids; a run uses your model.

- **Gemini.** Requests go to Google's OpenAI-compatible endpoint (`https://generativelanguage.googleapis.com/v1beta/openai`) with your key. The default model is `gemini-3.8-flash`. Google is limiting new access to Gemini 2.5 models, so use a 3.x model. **Test connection** lists the models your key can use and tries the saved model (see below).
- **OpenAI-compatible.** Enter the base URL (for example `https://api.openai.com/v1` or `http://localhost:11434/v1`), a key if the server needs one, and a model name. Plain `http` works on this computer and your own network; BridgeClip's network guard lets the job reach only that host and port. Use a model with a long context window (32,000 tokens or more): a long transcript does not fit in a small one. Ollama uses its default context (4,096 tokens on most computers) and cuts longer input down to fit without an error, so Settings shows a warning to set `OLLAMA_CONTEXT_LENGTH` when the URL uses Ollama's port 11434 or an `ollama` host name. Turn on **This model can read images** only for vision models; otherwise visual-only planning is unavailable and framing uses the built-in face tracking. **Wait for a reply** (5 to 120 minutes, 30 by default) is how long one request may take, for clip planning and frame checks alike; local models on a CPU can need many minutes for a long video.
- **Transcription.** Cloud transcription runs on OpenRouter. Choosing Gemini or a custom endpoint while no OpenRouter key is saved also switches transcription to Local Whisper, and Settings says so. Going back to OpenRouter undoes that switch, unless you changed the transcription source yourself in between.

### Review, repairs and metadata with your own model

With Gemini or an OpenAI-compatible endpoint, the features that run on OpenRouter services otherwise use your model:

- **Review.** `engine/clip_engine/services/model_judge.py` answers the same yes/no, choice and score questions that TypeSafe Jev answers on OpenRouter, for Review & edit, the optional review of automatic clips (Settings → TypeSafe Jev) and the clip editor's Review. The model is asked for probabilities only. An answer with a value outside 0 to 1 (such as a percentage), a missing option, or probabilities that do not add up to about 1 (±0.15) is refused rather than rounded into a confident pass; BridgeClip then derives the choice and score and checks the answer with Jev's own validator. The thresholds are the same numbers, but a model's probabilities are less calibrated than Jev's, so check the first results. Untrusted source context is never shown to the reviewer, as with Jev. Request counts, the token budget (reconciled with the tokens each request reports, or estimated when a server reports none) and the four-failure cut-off match Jev's. On a custom endpoint the review sends one request at a time, since a local server answers one at a time, and waits up to ten minutes for a reply; a rate-limit wait comes on top of that instead of ending the review.
- **Repairs and visual context.** Clip repair proposals use your model, and its reply is read like the planner's (reasoning and code fences are handled). Visual context uses your model only when it can read images (always for Gemini; for a custom endpoint only with **This model can read images** on); otherwise no frames are sent and the option is unavailable in Settings, so clips are judged on their dialogue.
- **Titles and captions.** Library and Automations metadata are written by your model through `src/main/ai-chat.ts`, which sends requests the way the engine does. Clips are transcribed the way **Speech to text** is set: Cloud (OpenRouter), the built-in Whisper (the engine's `whisper_setup.py transcribe` command, model loaded once per clip; it never downloads a model that is not installed, stops after 30 minutes and when the app quits, and uses the CPU while a clip job is running so the two do not compete for video memory) or your Whisper server. This also applies with OpenRouter as the provider: if Speech to text is Local Whisper, the audio for titles and captions stays on your computer too.
- **Still OpenRouter-only.** Web research (of the source before clipping, and the optional research step of metadata writing) uses OpenRouter's web search, so it is off with other providers; metadata writing continues without it.
- **Presets.** Quality, Economy and Advanced are OpenRouter model presets. With another provider the Create page says so and every run uses the saved model.

### Test connection

For Gemini and OpenAI-compatible endpoints, **Test connection** uses the saved settings and sends requests shaped like a clip job's, then shows one line per check:

- **Server**: the model list at `{base URL}/models` (10-second limit), for the model suggestions. A clip job never asks for it, so only "nothing is answering" (a refused connection, named by address and port, such as "Nothing is answering at localhost:3001") or an unknown host stops the test there. A missing list, a key without permission to read it, or a slow list do not.
- **Key**: accepted, rejected, out of credit, or "no key was sent, and the server did not ask for one". The key line only says "accepted" after the model answered.
- **Model**: one request with the saved model, built the way the engine builds the planner's: a system message, the prompt as a list of parts with the JSON schema added, temperature 0.2 (none for Gemini 3 and reasoning models), and the planner's 32,000-token output allowance. It learns what the server asks for as a job does: it drops a refused temperature, switches to `max_completion_tokens`, or lowers the allowance to a stated limit. It waits up to the endpoint's **Wait for a reply** setting, at most five minutes (two minutes for Gemini). A missing model, a URL without `/v1`, a key the server refuses, too small a context window, a rate limit, a daily quota and a server still loading its model each get their own message.
- **JSON answers**: the request steps down from strict schema to JSON mode to plain text, as a job does, and the answer is read the way the engine reads it (reasoning before it, code fences, prose and trailing commas are handled). A model that answers in prose fails this line, because clip planning needs JSON. A model that uses up its whole allowance before answering gets a warning instead.
- **Images** (custom endpoints only; Gemini models always read images): a 64×64 image whose left and right halves have two different colours, picked at random each run. The model passes only if it names both, so a model that cannot see the image, or a proxy that drops it, cannot pass by guessing. The image request steps down the same way a job's frame check does. When the result disagrees with **This model can read images**, Settings offers to switch it.

A result is hidden once the URL or model changes, so it never stands for settings it did not test. The test makes the model-list request and, for a custom endpoint, two to about eight short chat requests (more only when the server asks for changes); Gemini gets the list request and one or a few chat requests. OpenRouter's test checks the key only, because its models come from the Quality, Economy or Advanced choice; OpenRouter's balance needs a separate management key, so it is not shown. Messages are fixed sentences plus the model name and address you entered; nothing a server sends is shown.

### Structured output

The planner asks for strict JSON-schema output and also writes the schema into the prompt, because some servers accept `response_format` and then ignore it without an error. If a server rejects the schema (HTTP 400 or 422), BridgeClip retries with JSON mode, then with plain text, and remembers what worked for the rest of the job. A server that rejects `temperature` gets the request again without it, and the next requests leave it out; structured output is not weakened for that. Replies wrapped in code fences or prose are recovered, and reasoning that models such as DeepSeek-R1 and Qwen3 write first, in `<think>…</think>`, is removed before the JSON is read. A model that cannot follow the schema produces a "could not parse" failure rather than guessed clips.

### Errors

Provider failures are classified into fixed messages: key rejected, model not found, nothing at the endpoint URL (a 404 that does not mention a model, usually a base URL without `/v1`), rate limit or quota reached, account out of credit, unreachable, too slow to answer, temporarily unavailable, and request rejected. A 404 is told apart by the message, or by whether the same base URL lists models. On a rate limit BridgeClip waits as long as the provider asks, up to 90 seconds, twice: from the `Retry-After` header, or from the error body, where Gemini puts it (RetryInfo's `retryDelay`, or "Please retry in 40s" in the message). A Gemini daily quota is not waited out. A request that runs past **Wait for a reply** is not retried, since asking again would wait just as long. Gemini 3 models keep their default temperature, as Google recommends. The provider's own error text is kept out of the UI, and logs only record a truncated copy.

Frame checks stop for the rest of a job when they cannot work: at once for a rejected key, a missing model, a wrong URL, a rate limit still in force after waiting, or a model that took longer than five minutes for one frame; and after two rejected frames in a row otherwise. A single rejected frame falls back to face tracking for that shot only. A frame check from a custom endpoint waits at most five minutes, whatever **Wait for a reply** says.

### Tests

`engine/tests/test_ai_client.py` covers payload preparation, the structured-output fallback levels, the schema in the prompt, reasoning removal, the temperature retry, status-code mapping including a wrong URL path, rate-limit waiting from headers and Gemini error bodies, the wait setting, and the redirect and size limits against an offline streaming transport. `engine/tests/test_vision_resilience.py` covers when frame checks stop. `engine/tests/test_local_whisper.py` covers word cleaning, both backends, a real local HTTP server for server mode and the integration with chunking and costs. `bridge/test_network_guard.py` covers the endpoint allow-list, including link-local and DNS-rebinding cases. Neither suite calls a paid provider.
